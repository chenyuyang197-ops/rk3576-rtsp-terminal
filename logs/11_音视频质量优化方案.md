# 音视频质量优化方案（电音 + 偶发糊帧）

> 工程：`rk3576-rtsp-terminal`  
> 日期：2026-08-21

## 一、现象与根因

### 1. 背景「电音 / 嗡声 / 滋滋声」

| 可能来源 | 机制 | 在本板上的表现 |
|----------|------|----------------|
| **硬件增益过高** | ES8388 Capture Digital Volume 默认 **192（满刻度）** + PGA=3，ADC 过载产生谐波 | 听感像「电音/破音」，尤其 volume=4.0 软件再放大 |
| **工频干扰** | 50 Hz 电源/地线耦合 | 持续低频嗡声 |
| **ALSA 欠载** | `alsasrc` 无 buffer，偶发 xrun → 咔嗒/金属音 | 间歇性 |
| **静音段底噪被放大** | 高 gain 把本底噪声一起推上去 | 不说话时更明显 |
| **双进程抢麦** | preview + encoder 同时 `hw:0,0` | 已用顺序启动规避 |

EASY-EAI **无** 降噪/AEC，靠 **适中硬件增益 + FFmpeg AAC 64k**；我们 v2/v4 用 **软件 volume 4.0** 反而放大底噪。

### 2. 录制画面偶发糊

| 可能来源 | 机制 | 在本板上的表现 |
|----------|------|----------------|
| **ISP 3A 未收敛** | AE/AWB 仍在调整 → 曝光时间变长 | 运动/亮度变化时整帧发糊 |
| **P 帧码率不足** | CBR 下 I 帧占大头，P 帧被压到几 KB | v3 曾出现 P 均码 **2654 B** |
| **1080p→720 缩放** | `videoscale` 双线性软化 | 细节不如传感器原生输出 |
| **GOP 过长 + 限 QP** | I 帧间隔大且 P 帧 QP 高 | 周期性「突然清晰一下再糊」 |

## 二、分层解决方案

### A. 硬件 / 驱动层（优先）

```bash
# 板端执行（已封装 scripts/board_audio_tune.sh）
amixer -c 0 cset numid=50 140,140      # Capture Digital Volume 降 ~12 dB
amixer -c 0 sset 'ADC PGA Gain' 2       # PGA 降低，防失真
amixer -c 0 cset numid=41 3             # ALC Stereo 自动限幅
amixer -c 0 cset numid=48 1             # 噪声门 NG
```

**接线建议**：麦克风远离 Switch 电源/HDMI 走线；USB 供电录音时加磁环或独立 5V 适配器。

### B. 音频 GStreamer 链路（v5 已实现）

```
alsasrc buffer-time=200ms
  → audioconvert
  → high-pass 80 Hz（去工频/隆隆声）
  → audiodynamic expander（噪声门，压静音段底噪）
  → volume 2.5（硬件 ALC 已增益，软件少放大）
  → voaacenc 128k
```

**环境变量**：

| 变量 | 默认 | 说明 |
|------|------|------|
| `ENC_AUDIO_GAIN` | 2.5 | 软件增益，过大易电音 |
| `ENC_AUDIO_HPF_HZ` | 80 | 0=关闭高通 |
| `ENC_AUDIO_NR` | 1 | 0=关闭 expander 噪声门 |
| `ENC_AUDIO_BITRATE` | 128000 | AAC 码率 |

**若仍有 50 Hz 嗡声**：后续可加 `equalizer-nbands` 在 50 Hz 处 -12 dB（需实测频谱）。

**终极方案（工作量大）**：板端编译 `gst-plugins-bad` 的 `webrtcdsp`（AEC/NS/AGC），或改用 EASY-EAI 式 ALSA 直采 + MPP/FFmpeg 路径。

### C. 视频 / ISP 层（v5 已实现）

| 措施 | 参数 | 目的 |
|------|------|------|
| 延长 ISP 预热 | `MIN_ISP_SEC=50`，`WARMUP=60`，`video>=400` 才开录 | AE/AWB 收敛 |
| 丢不稳定前帧 | `ENC_CAM_SKIP_FRAMES=15` | 对齐 EASY-EAI skip 10 |
| 抬高 P 帧下限 | `bps=3M bps-min=2.25M bps-max=3.6M qp-delta-ip=2` | P 帧不再被压到 2 KB |
| 短 GOP | `gop=15`（@30fps） | 周期性 I 帧恢复清晰度 |
| 1080p 采集 + scale | `cameraWidth=1920` | v4 实测优于 720 直采 |

**若仍偶发糊（ISP 层）**：

1. 用 `rkaiq_tool` / IQ 文件 **锁定曝光**（固定 shutter，牺牲低光）
2. 录制前仅跑 publisher、**关闭 preview 占 MIPI**（`localNv12Tap=0` 专用配置）
3. 换 **VBR/AVBR** 做对比：`mpph265enc rc-mode=vbr bps=3500000`

```bash
source audio-video/rk3576-rtsp-terminal/scripts/adb_env.sh
bash audio-video/rk3576-rtsp-terminal/scripts/deploy.sh

# P 帧均码（应 > 5 KB，接近 v2）
ffprobe -select_streams v -show_entries packet=size,flags -of csv=p=0 samples/rtsp_camera_av_v5.ts \
  | awk -F, '{if($2~/K/){i++;is+=$1}else{p++;ps+=$1}} END{print "I avg",is/i,"P avg",ps/p}'
```

## 四、版本选型建议

| 版本 | 适用 | 不推荐原因 |
|------|------|------------|
| **v2/v4** | 当前最好基线 | 电音=高 gain；偶发糊=ISP 未稳 |
| v3 | — | 720 直采 + 限 QP，全面退步 |
| **v5** | 下一步试听 | 硬件 ALC + 噪声门 + 长预热 + P 帧下限 |

## 五、与 EASY-EAI 的差异（为何不能照搬）

- EASY-EAI：**闭源 rkaiq + easymedia** 内部处理 3A，应用层无降噪
- 我们：**GStreamer + 显式调参**，必须自己管 ES8388 增益和 ISP 预热
- 电音问题：**EASY-EAI 无此问题因未做 4× software gain**；糊帧靠 ISP 库而非编码器 QP
