## 1. 外网 PC VLC 拉流

### 现状

- 板端 `end0` 已配 **192.168.1.100/24**，当前 **linkdown**（未插网线）。
- 板内自环走 `lo` + `192.168.1.100/32`，**不依赖外网**。

### 方案 A：无网线（推荐，5 分钟）

用 **adb TCP 转发**，PC 上 VLC 访问 `127.0.0.1`，简历可写「PC 经 adb 转发拉流验收」：

```bash
# 1) 板端先起发布（任选一个）
source audio-video/rk3576-rtsp-terminal/scripts/adb_env.sh
adb push ... # 若脚本未 deploy
adb shell /home/lckfb/rk3576-rtsp-terminal/scripts/run_rtsp_audio_verify_board.sh
# 或单独起 publisher_loopback.ini

# 2) PC/WSL 转发 + 自动探测
bash audio-video/rk3576-rtsp-terminal/scripts/run_vlc_pc_verify.sh 8554 554 15

# 3) Windows VLC 手动
#    媒体 -> 打开网络串流 -> rtsp://127.0.0.1:8554/live
#    截图：画面 + 工具->编解码器信息（H.265 + AAC）
```

**验收数据写入简历：** PC 侧 pull ≥50 KB H.265 / VLC 能播 / ffprobe 见 video+audio 轨。

### 方案 B：真网线（面试更直观）

1. PC 网卡设静态 **192.168.1.101/24**，网线接板 `end0`。
2. 确认 `adb shell ip -br addr` 中 `end0 UP`。
3. PC VLC：`rtsp://192.168.1.100:554/live` 与 `/live2`。
4. 双路各截图一张。

## 2. RTSP 路径听音

### 现状（易混淆）

| 路径 | 已验？ | 说明 |
|------|--------|------|
| 麦克风 → encoder → **local tap** → faad 扬声器 | ✅ | `run_mic_verify_board.sh` |
| 麦克风 → encoder → **RTSP AAC 轨** → 客户端解码播放 | ❌ | 这才是「RTSP 路径听音」 |

`player` 的 `audio_playback_thread` 读的是 **preview_audio shm（local tap）**，不是 RTSP 拉回来的 AAC。

### 补法（板端即可，无需 PC）

```bash
adb shell /home/lckfb/rk3576-rtsp-terminal/scripts/run_rtsp_audio_verify_board.sh
# 可选第二参数 URL：rtsp://192.168.1.100:554/live2
```

脚本流程：起 `publisher_mic.ini` → gst-discoverer 确认 AAC 轨 → **rtspsrc → rtpmp4adepay → aacparse** 落盘计数 → 可选 **autoaudiosink** 5s 听音。

**PASS 阈值：** SDP 含 audio + `/tmp/rtsp_audio.aac` ≥ 8 KB。

**简历写法：** 「RTSP 双轨 SDP 含 AAC；板端 rtspsrc 拉流 ADTS ≥N KB / 扬声器可听」。

## 3. 30 min 双路 ch1 长稳

### 现状

| 场景 | ch1 | 原因线索 |
|------|-----|----------|
| `run_resume_verify_board.sh` 120s | ✅ push≈1100 | ch0 先拉 10s 再启 ch1；配 end0+lo |
| `run_stress_test_board.sh` 1800s | ❌ push=0 | 旧脚本仅 lo；长稳未采样 push1 |

120s 已 PASS 说明 **架构 OK**；长压 ch1=0 更像是 **压测脚本环境/观测** 问题，而非双 mount 设计缺陷。

### 已修（2026-08-21）

- 压测脚本对齐 resume：`end0/eth0` + `192.168.1.100/24`
- 每 30s 日志增加 **push0/push1**
- PASS：`push0≥1000` 且 **push1≥500**；仅 ch0 则 PARTIAL

### 复跑命令

```bash
# deploy 新脚本
bash audio-video/rk3576-rtsp-terminal/scripts/deploy.sh

# 先快速冒烟 5 min（可选）
adb shell /home/lckfb/rk3576-rtsp-terminal/scripts/run_stress_test_board.sh \
  /home/lckfb/rk3576-rtsp-terminal/run 300

# 看 push1 是否在 t=120s 后 >0
adb shell tail -20 /tmp/stress_test_result.txt

# 正式 30 min
adb shell /home/lckfb/rk3576-rtsp-terminal/scripts/run_stress_test_board.sh \
  /home/lckfb/rk3576-rtsp-terminal/run 1800
```

### 若 push1 仍长期 0

1. 抓日志：`adb shell grep -E 'ch=1|live2|error' /tmp/stress_preview.log | tail -40`
2. 单独拉 live2：`adb shell timeout 15 gst-launch-1.0 rtspsrc location=rtsp://192.168.1.100:554/live2 ...`
3. 代码侧可加大错峰：`preview/main.c` 中 ch0 后 `sleep(10)` → `sleep(15)`
