# 踩坑与修复记录（详细）

> 每条格式：**现象 → 根因 → 修复 → 验证命令 → 状态**

---

## 1. eMMC 优先启动，TF 卡不生效

**现象**：插 TF 仍进 Android 14，`adb shell getprop` 显示 userdebug。  
**根因**：RK3576 启动顺序 eMMC > TF；出厂 Android 在 eMMC。  
**修复**：RKDevTool → 高级功能 → **擦除所有**；SD_Firmware_Tool 勾 **SD启动** 写 Ubuntu 镜像。  
**验证**：
```bash
adb shell "cat /etc/os-release | head -1; findmnt /"
# Ubuntu 24.04.4 LTS，/ on mmcblk1p8
```
**状态**：✅ 已解决

---

## 2. WSL adb 找不到设备

**现象**：`adb: command not found` 或 `adb devices` 空。  
**根因**：① PATH 未配 ② USB 在 Windows 侧 ③ 误用 `127.0.0.1` 启 WSL 本地 adb。  
**修复**：
```bash
export PATH="$HOME/.local/android/platform-tools:$PATH"
export ADB_SERVER_SOCKET=tcp:$(ip route show default | awk '{print $3}'):5037
```
Windows 先 `adb devices` 启动服务。  
**验证**：`adb shell uname -m` → `aarch64`  
**状态**：✅ 已解决

---

## 3. Live555 编译失败（openssl）

**现象**：`fatal error: openssl/ssl.h: No such file or directory`  
**根因**：板端无 libssl-dev；live555 默认含 TLS 头。  
**修复**：`genMakefiles linux-no-openssl`；`rtsp_server` 编译加 `-DNO_OPENSSL=1`；链接去掉 ssl/crypto。  
**验证**：`make rtsp_server` 成功，产物 ~916KB  
**状态**：✅ 已解决

## 4. Live555 ExternalProject 找不到 liveMedia/Makefile

**现象**：`cannot create liveMedia/Makefile: Directory nonexistent`  
**根因**：CMake ExternalProject 在错误 cwd 执行 genMakefiles。  
**修复**：
```cmake
CONFIGURE_COMMAND ${CMAKE_COMMAND} -E chdir ${LIVE555_DIR} ./genMakefiles linux-no-openssl
BUILD_COMMAND ${CMAKE_COMMAND} -E chdir ${LIVE555_DIR} ${CMAKE_MAKE_PROGRAM} -j4
```
**状态**：✅ 已解决

## 5. MPP 直编输出过小（~265B/帧）

**现象**：`shm_dump` 仅 5314B/20 帧；RTSP 视频 0 字节。  
**根因**：`mpp_encoder_encode` 单次 `encode_get_packet` 不足；直写 API 与 GStreamer 管线行为不一致。  
**修复**：`encoder_main.c` 改用 GStreamer `videotestsrc ! mpph265enc ! h265parse ! fdsink`，读 pipe 写 shm。  
**验证**：冒烟 t.h265 1240063B；自环 ch0.yuv 1382400B  
**状态**：✅ 已解决（保留 `common/mpp_codec.c` 供后续直调）

## 6. H265VideoStreamDiscreteFramer 报 start code 错误

**现象**：日志刷屏 `H264or5VideoStreamDiscreteFramer error: MPEG 'start code' seen in the input`  
**根因**：DiscreteFramer 期望无 start code 的 NAL；MPP/GStreamer 输出 Annex B（含 0x000001）。  
**修复**：`rtsp_server_main.cpp` 改用 `H265VideoStreamFramer::createNew`。  
**验证**：GStreamer rtspsrc PLAY 成功  
**状态**：✅ 已解决

## 9. rtsp_server attach shm failed（启动顺序）

**现象**：`[E] attach shm failed`，encoder 与 rtsp_server 同时启动。  
**根因**：`fq_pool_create` 在 encoder，`fq_pool_attach` 在 rtsp_server；server 先起则失败。  
**修复**：`publisher/main.c` 先 `sup_start_all` encoder，`sleep 2`，再 fork rtsp_server。  
**状态**：✅ 已解决

## 11. encoder 无限运行导致 adb shell 挂起

**现象**：`encoder 1280 720 25 0` 不退出，后续命令阻塞。  
**根因**：seconds=0 时 gst is-live 常开；曾用 alarm 无效。  
**修复**：有限时长用 `num-buffers=fps*seconds`；后台跑需 `timeout` 或 `pkill`。  
**状态**：✅ 已规避

## 12. 板子时钟 skew（Clock skew detected）

**修复**：不影响二进制；可 `date -s` 同步或忽略。

## 13. Live555 读 64KB 块导致 StreamParser 崩溃

**现象**：`StreamParser internal error (655363 + 1 > 600000)`，`rtsp_server` SIGABRT；双客户端时 TCP 丢包刷屏。  
**根因**：encoder 将 65536B fread 块当作一帧 push；Framer 期望 AU 粒度。  
**修复**：`encoder_main.c` / `rtsp_channel_main.c` 按 Annex B start code **切分 AU** 再入队。  
**状态**：✅ 已解决

---

## 14. 预览端 attach shm failed（与发布端键冲突）

**现象**：`video shm attach failed`；2 路 preview 无法同时 attach。  
**根因**：预览 `rtsp_channel` 与发布 encoder 共用 `0x5200` 键空间；channel 1 未 create。  
**修复**：新增 `fq_preview_*`（`0x5300`）；`preview_supervisor` 先 `fq_preview_pool_create(N)`。  
**状态**：✅ 已解决

## 15. 板端无 IP 导致 Live555 异常

**现象**：`Unable to determine our source address`；RTSP 双客户端 TCP buffer full。  
**根因**：end0 无 carrier 时未配 IPv4，Live555 绑定/RTCP 异常。  
**修复**：`net_init.c` 无 carrier 仍按 INI 给 end0 配静态地址；rtsp_channel 可改 UDP。  
**状态**：⚠️ 部分缓解，双路仍待稳

## 20. MPP 硬解无输出 / 无 YUV dump

**现象**：`rtsp_channel` push 2000+ 帧，`player` 无 `dump /tmp/ch0.yuv`。  
**根因**：`mpp_decoder_decode` 收到 `info_change` 帧后未 `MPP_DEC_SET_INFO_CHANGE_READY`，解码卡住。

**状态**：✅ 已解决

## 22. v4l2-ctl 强设 NV12 导致 GStreamer 摄像头失败

**验证**：

**状态**：✅ 已解决

## 23. MIPI 显示变形 / RGA letterbox 花屏

**现象**：480×800 MIPI 屏画面拉伸、花屏或闪烁；preview.log 大量 `imresize error factor=0.625`。  
**根因**：
1. 720×1280→480×800 非等比缩放（fx≠fy）导致拉伸；
2. letterbox 目标宽 450 未 **16 字节对齐**，RGA `improcess`/`imresize` 失败；

**修复**：
- `display_rga.c`：等比 letterbox + 缩放宽高 `& ~15` 对齐；
- `loopback.ini`：`rotateSeconds=0`；
- `rtsp_server`：`RkRTSPServer` 强制 IPv4 bind。

**验证**：

**状态**：✅ 已解决

## 24. `/live` 与 `/live2` 双 mount 抢同一 shm 队列

**现象**：ch0 有 push，ch1 长期 0 帧；或 live2 discoverer 报 `Could not decode stream`。  
**根因**：两路 `ShmServerMediaSubsession` 均 `fq_pop(0, VIDEO)`，多客户端抢帧 + 新连接 `fq_flush` 互相干扰。  
**修复**：`encoder` 镜像 push 至 ch0/ch1；`rtsp_server` `/live`→ch0、`/live2`→ch1；INI `rtspStreamChannels=2`。  
**验证**：
```bash
adb shell /home/lckfb/rk3576-rtsp-terminal/run/rtsp_channel 1 rtsp://192.168.1.100:554/live2
# 期望 push seq=200+ / 10s
```
**状态**：✅ 单路 ch1 已通；full preview+player 下 ch1 仍待稳

## 26. 压测脚本 `SECONDS` 与 bash 内置变量冲突

**现象**：`run_stress_test_board.sh` 日志 `t=` 约为实际 wall time 的 2 倍；`duration=1800s` 但采样超过 3600。  
**根因**：bash 内置 `SECONDS` 每秒自增，与脚本参数同名导致 `ELAPSED` 计算偏大（`END - SECONDS` 随时间缩小）。  
**修复**：参数改名为 `STRESS_SEC`；`START_TS`/`END_TS` 固定 wall clock；`LOAD_MAX` 取 max。  
**验证**：
```bash
adb shell /home/lckfb/rk3576-rtsp-terminal/scripts/run_stress_test_board.sh .../run 120
# 期望 t≈120 结束，非 240
```
**状态**：✅ 脚本已修；2026-08-21 首轮 30 min 数据仍有效（wall ~1800s，ch0 push≈38900）
